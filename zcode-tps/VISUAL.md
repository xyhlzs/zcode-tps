# TPS 小窗 · 视觉方案 v1

只管「好看好不好看、看得清看不清」，不管数据从哪来（那是 DESIGN.md v2 的事）。
所有方案都约束在现有实现路径内：PowerShell 5.1 + WinForms + GDI+ 自绘 Paint，
没有任何 WebView/WPF 依赖，所以每个建议都标注了 GDI+ 可行性。

---

## 1. 现状诊断

对着 `monitor/tps-monitor.ps1` 的 Paint 逻辑逐条看：

| # | 问题 | 依据 |
|---|---|---|
| V1 | **主题与宿主脱节**。浅灰底 (#F9FAFB) 卡片贴在深色 ZCode 窗口旁边，是屏幕上唯一一块亮色；默认 0.8 不透明度叠在深色背景上，浅色卡会变成脏灰。半透明只对深色表面友好 | 底色 `FromArgb(249,250,251)` + `$form.Opacity = 0.8` |
| V2 | **数字会抖**。大数字用比例字宽的 Segoe UI，每次刷新（400ms 一次）数字宽度都变，后面的 "tok/s" 跟着左右跳；`{0:N1}` 进位时（9.9→10.1）更明显 | `Fonts.big = Segoe UI 26 Bold`，unit 坐标依赖 `MeasureString` |
| V3 | **层级过平**。本轮/平均/最高三行同字号同列宽，占掉窗口约 1/3 高度，和主数字抢注意力；页眉 "ZCode TPS" 又占一行——用户自己拉起的小窗，不需要自我介绍 | Paint 中 y=112/128/144 三行 + y=9 页眉 |
| V4 | **柱状图看不见也站不稳**。历史柱 alpha 48 的蓝叠在浅灰底上几乎隐形；纵轴归一到会话最大值，每次刷新出新高，全部柱子瞬间重缩放，图会「呼吸」 | `barDim = 48 alpha`，`max = spark 最大值` |
| V5 | **关闭钮不可见**。右上角 "×" 用 muted 色画在浅底上，视觉上找不到，但 34px 命中区一直在；用户既怕点错又找不到怎么关 | `DrawString('×', …, faint)` |
| V6 | **状态信号太弱**。生成中/空闲的唯一区别是 7px 圆点变个色；数字、图、文字全部纹丝不动，分不清「在慢慢生成」和「卡了」 | live 点 `16,185,129` vs idle `209,213,219` |
| V7 | **页脚是长句**。`模型名 12 req 3s 前` 把三种不同性质的信息（对象/计数/时间）挤成一行 muted 小字，想扫读哪个都得逐字读 | Paint y=160 |

一句总评：这不是「配色不好看」的问题，是**信息优先级和表面处理**的问题——
真正的主角（那个数字）被次要信息和平庸的底色稀释了。

## 2. 设计立场

- **数字即界面**。这扇窗的全部价值就是那个速率数字，让它占视觉权重的 70%；
  其余信息全部降一级、收进角落。chrome（页眉、边框、关闭钮）能删的删。
- **色彩只编码状态，不搞装饰**。全窗只有数字是白的，其余是灰阶；颜色只在
  表达「现在什么状态」时出现（在飞=绿、估算=琥珀、出错=红）。同一时刻最多
  一种彩色在场。
- **融入而不是覆盖**。它是贴在深色 IDE 旁边的随从窗，用深色底 + 半透明，
  让它看起来像宿主的一部分。
- **数字不能抖**。所有会实时变化的数值一律用等宽数字排版，位置锚定，
  只换内容。

自校准说明：深底 + 绿点缀容易滑向「黑客终端」的俗套。这里的防俗设计是——
绿色只出现在 3.5px 的状态点和柱状图最近一柱上（且空闲时消失），主角数字是
纯白而非荧光色；等宽字体用在数字上是功能理由（防抖），不是风格贴纸。

## 3. Token 方案

### 3.1 色板（深色）

| 名称 | 值 | 用途 |
|---|---|---|
| surface | `#1A1D22` | 窗底（配合默认不透明度 0.85） |
| ink | `#F2F4F7` | 主数字、会话标题 |
| sub | `#9AA1AB` | 单位、次级标签 |
| faint | `#5C6470` | 页脚元信息、历史柱 |
| live | `#34D399` | 在飞状态点 + 柱状图最近一柱 |
| estim | `#E5B567` | 估算速率的 "≈" 前缀（预留 v2 L3） |
| error | `#E5484D` | 错误状态点与错误文案 |
| idleDot | `#4A5058` | 空闲状态点 |

深底上不再画 1px 浅色描边——半透明下那条边是整圈「亮框」，删掉后只靠圆角
(6px) 和底色差异分界。空闲时整个数字从 ink 降为 sub，状态一眼可辨。

### 3.2 字体

| 角色 | 字体 | 字号 | 说明 |
|---|---|---|---|
| 主数字 | Cascadia Mono SemiBold | 30pt | 等宽防抖；回退链 Cascadia Mono → Consolas |
| 单位/标签 | Segoe UI（中文自动回退雅黑） | 8–8.5pt | 常规体，不加字距 |
| 会话标题（v2 多行） | Segoe UI | 8.5pt | 截断加省略号 |
| 行内速率（v2 多行） | Cascadia Mono | 9pt | 同列右对齐，纵向可扫读 |

回退链用「首个已安装家族」helper 实现（GDI+ 不做自动回退到指定备选）。
等宽字体这里是主题相关的选择：数据来自代码代理的 token 流，且 GDI+ 不支持
OpenType 的 `tnum` 特性，等宽是拿到表格数字的唯一途径。

## 4. 布局

### 4.1 单会话紧凑卡（默认）

高度从 190 压到约 140，宽度 240→216，内容收紧。落地时把「本轮/平均/累计/最高、
会话短码」全部保留（REQUIREMENTS 的 FR1-5/6/7 是硬需求，视觉层级靠主数字的
体量与颜色对比表达，不靠删信息）：

```
┌────────────────────────────────┐
│ ●  72.4 tok/s       id a348…   │  ← 点 + 主数字 + 单位 | 右上短码/计时
│                                │
│ ▂▃▅▆█▆▅▄▃▂▃▅▆▇█▆▅▃▂▁▂▃▄▅▆▇   │  ← 全宽 26px 柱状图
│                                │
│ GLM-5.3-Flash    重命名所有…  │  ← 右列：会话标题（sidecar 在场时）
│ 本轮 3,214 tok          平均 58.2 │
│ 累计 21,304 tok         最高 61.4 │
└────────────────────────────────┘
```

- 元信息首行右列：标题 sidecar（DESIGN.md §7.1 最小版）取到当前会话标题时显示
  标题（半窗内截断加省略号，FR1-5「人能读懂的归属」），req 计数退到 status.json；
  取不到时维持 req 计数，受限模式仍优先标注精简模式。

- **删掉页眉 "ZCode TPS"**：窗口身份由内容表达，省出一整行。
- 主数字区垂直留白加大，是全窗唯一的「大声」元素；空闲时数字变 sub 色。
- **右上角一槽两用**：生成中显示本次请求已进行的秒数（`12.4s`，DESIGN.md 的
  L1 信号，计时来源是日志 `model.request.started/completed` 配对）；空闲/等待
  时让给会话短码 `id a348…`（FR1-5 归属可核对）。这同时解决了 V6「分不清
  在不在跑」：点变色 + 数字变亮 + 计时在走，三重信号。
- 元信息三行左列是对象与累计、右列是速率口径，全部右对齐到右边缘，取代现在
  的连排长句（修 V7）。
- 关闭钮：默认不画，鼠标悬停整窗时右上角淡入 `×`（MouseEnter/Leave 置个布尔，
  Paint 里分支画），命中区不变。修 V5，且平时 chrome 为零。

### 4.2 柱状图修正

- 历史柱从 alpha-48 蓝改为实色 faint `#5C6470`，最近一柱用 live 绿——
  「哪根是最新」不需要图例就能看出来。
- 纵轴最大值加**迟滞**：新最大值立即采用，之后每次刷新只允许 max 衰减
  （如 ×0.995/帧）向下限靠拢，杜绝整图重缩放的「呼吸」。
- 柱间距从 1.5px 收到 1px、柱宽下限 2px，40 根在 204px 里刚好铺满。

### 4.3 多会话模式（对齐 DESIGN.md v2）

单会话卡上方叠加行列表，每行 20px；在飞行插入最上并整行提亮：

```
┌────────────────────────────────┐
│ ● 72.4 tok/s            12.4s  │   ← 在飞会话即主数字区
│ ▂▃▅▆█▆▅▄▃▂▃▅▆▇█▆▅▃▂▁▂▃▄▅▆▇   │
├────────────────────────────────┤
│ 重命名所有文件           48.1  │   ← 空闲行：标题左、速率右(等宽)
│ MSPL λ=0.5 模块实验      31.7  │
│ 软著合作开发协议           —   │
└────────────────────────────────┘
```

- 在飞会话直接**升级为主数字区**（不重复占行），空闲行只留在列表里；
  没有任何会话在飞时，主数字区显示最近会话的平均值并降为 sub 色。
- 列表行不画边框不画斑马纹，靠 20px 行距分界；行数超 5 折叠为 `+N`。

## 5. 状态规范

| 状态 | 点 | 主数字 | 附加 |
|---|---|---|---|
| 在飞（真值） | live 绿 | ink 白，`72.4` | 右上计时走动 |
| 在飞（估算，v2 L3） | live 绿 | estim 琥珀，`≈62` | 计时照走；单卡主数字与多行在飞行同规 |
| 空闲 | idleDot | sub 灰 | 计时位空，柱图全灰 |
| 等待新会话 | idleDot | sub 灰 `—` | 页脚「该会话暂无生成数据」 |
| 错误 | error 红 | sub 灰 `—` | 页脚显示错误短句 |

## 5.5 多行模式（v2 落地，0.3.0）

并发多任务时的并列展示（DESIGN.md §7.2），落到 VISUAL 约束内的决定：

- **头部回来了一行**：单卡时「ZCode TPS」页眉被删（内容即身份），多行模式下
  行数多了需要一个锚点，头部恢复为「全局状态点 + ZCode TPS」+ 悬停 ×。
- **在飞行高亮**：`rowHi #232830`（surface 提亮一档）铺一条整行底色——多行模式里
  唯一的表面变化，绿色点仍是唯一的彩色状态信号；估算 `≈N` 是琥珀，遵守
  「同一时刻最多一种彩色在场」在行级成立（在飞行的琥珀与绿点不冲突：点标状态、
  数字标口径）。
- **行结构**：在飞行两行（标题 + 速率 / 计时 + 累计），空闲行单行；序号 faint、
  标题在飞 ink / 空闲 sub、速率列右对齐等宽（Cascadia/Consolas 9pt，VISUAL §3.2
  预告的行内速率落位）。速率为空显示 `—`。
- **折叠**：上限 5 行，尾部 `+N`（faint），不再多画任何装饰。
- **窗口尺寸**：宽 216 → 300（逻辑 px），高随行数自适应；单会话退回紧凑卡片，
  Region/关闭钮命中区同步重建。

## 6. GDI+ 落地注记

全部改动收敛在 Paint 处理器和两处初始化里，不动数据管线：

1. **Brushes/Fonts 表替换**：换 3.1/3.2 的值；字体回退 helper 约 10 行。
2. **悬停 ×**：`MouseEnter/MouseLeave` 置 `$script:Hovered`，Paint 分支 + 现有
   命中区判断不变。
3. **max 迟滞**：`$script:ChartMax` 一个标量，Paint 里更新。
4. **半透明+深底**：现有「Op<1 用灰度抗锯齿」的逻辑保留；深底上灰度抗锯齿
   的观感问题远小于浅底（没有彩边和脏灰混色）。
5. 默认不透明度建议 0.8 → **0.85**（深底可以更实一点而不显笨重）。

风险：Cascadia Mono 在没装 Windows Terminal 的 Win10 上不存在 → 回退 Consolas，
观感略降但等宽防抖保住；字号 30pt 的 Cascadia 在 200% DPI 下渲染锐利
（已有 PER_MONITOR_AWARE_V2），无需额外处理。

## 7. 被否掉的方向

| 方向 | 否决理由 |
|---|---|
| 换 WPF/WebView 重写界面获得亚克力/云母材质 | 破坏「单文件、零依赖、PS5.1 可跑」约束，收益只是材质 |
| 亮色主题微调（换强调色、加投影） | 不解决「与深色宿主脱节 + 半透明发脏」的根因 V1 |
| 给三行统计加图标/彩色徽章 | 与「色彩只编码状态」冲突，且加剧 V3 的层级拥挤 |
| 柱状图改折线 | 样本本来就是离散的「每次请求」一条，柱形语义更诚实；折线的连续感是假的 |
| 环形进度/仪表盘造型 | 速率没有 0–100% 的天然量程，仪表隐喻站不住，还占面积 |
