# ZCode TPS 监控 · 需求文档

版本 v1.3 · 2026-09-28 · 状态：需求基线（v1 已实现，v2 设计中）

需求原文（2026-09-28）：

> 我需要实时显示 ZCode 的 TPS，切换每个会话的时候，需要自动显示当前会话的
> TPS，子代理不统计。

追加需求（同日）：

> 还要显示当前对话最高的 TPS 和平均的 TPS，然后 TPS 小窗口透明度调低一些。

> 我希望 ZCode 窗口关闭或者最小化后，TPS 窗口也跟随着关闭或者窗口化。

关联文档：[DESIGN.md](DESIGN.md)（技术设计与实测依据）、[README.md](README.md)（安装与使用）。
本文档界定「要什么、做到什么程度算合格」；「怎么做到」见 DESIGN.md。

---

## 1. 背景与问题

ZCode 客户端不显示模型生成速率。用户等待长生成时无法判断系统是否在工作、速率
是否正常；ZCode 日常并发多个任务，用户在任务之间切换时，希望看到的始终是
「我正在看的这个任务」的速率。

落地形态的先决约束：ZCode 插件系统没有 UI 扩展点（只能贡献 skills / commands /
hooks / MCP / agents），界面内嵌显示做不到。因此由插件 hook 拉起一个独立于
ZCode 界面的置顶小窗，读取 ZCode 落盘的内部数据计算速率。

---

## 2. 术语与口径

| 术语 | 定义 |
|---|---|
| TPS | 模型输出速率（token/s）。口径：`response.usage.outputTokens ÷ durationMs`。`durationMs` 是一次模型请求的端到端耗时（含首字延迟 TTFT），所以该值是**端到端速率**，略低于模型纯解码速率。 |
| 最高 TPS | 当前会话内**单次模型请求**速率的最大值：逐请求按上面的口径计算后取最大。 |
| 平均 TPS | 当前会话的**合计口径**：Σ outputTokens ÷ Σ durationMs。这是按时长加权的平均，不是各请求速率的算术平均——前者与整段真实吞吐一致，后者会被短请求过度拉高。 |
| 模型请求 | 一次对模型的流式调用，rollout 中对应一条记录。一个回合内每多一次工具调用就多一次请求。 |
| 会话 | ZCode 里的一个任务/对话，磁盘标识 `sess_<uuid>`。 |
| 主会话 | 用户在界面上创建、可从侧边栏切换的会话。 |
| 子代理 | 主会话内由 Agent 工具派生的代理。会话 id 形如 `sess_subagent_agent_<uuid>`（实测样本见 §6）；db 中 `task_type = 'subagent_child'`。 |
| 在飞 | 已发出模型请求、尚未收到完成事件的状态。 |

## 3. 用户场景

| 编号 | 场景 |
|---|---|
| S1 | 单会话观察：发一条长指令，盯着窗口确认「在动、速率正常」。 |
| S2 | 切换跟随：从任务 A 切到任务 B，窗口自动改显 B 的数据。 |
| S3 | 并发多任务：同时跑多个任务（实测 258 次采样中 247 次并发 ≥ 2），数字要分得清属于谁。 |

## 4. 功能需求

### FR1 实时显示 ZCode 的 TPS

| 编号 | 需求 |
|---|---|
| FR1-1 | 显示当前会话最近一次模型请求的 TPS，口径见 §2；显示值必须与 rollout 真值重算结果一致。 |
| FR1-2 | 生成中与空闲在 1 秒内可区分；生成中界面每 ≤1s 有一次可见变化。 |
| FR1-3 | 生成过程中速率数字的更新要快于「一次请求」（在飞估算，标注 `≈`；真值到达后覆盖）。 |
| FR1-4 | 每个数字可溯源：真值 → 某条 rollout 记录；估算 → 字节采样与标定系数。不得显示无依据的数字。 |
| FR1-5 | 辅助信息：当前会话标识（人能读懂的标题）、模型名、本轮/会话累计输出。 |
| FR1-6 | 显示当前会话的**最高 TPS**（口径见 §2）；会话切换后随新会话重新统计。 |
| FR1-7 | 显示当前会话的**平均 TPS**（口径见 §2）。 |

### FR2 切换会话时自动显示当前会话的 TPS

| 编号 | 需求 |
|---|---|
| FR2-1 | 用户切到某个会话后，窗口无需任何手动操作即改显该会话的数据。 |
| FR2-2 | 跟随判定优先级：显式指定 > 用户激活事件（回车/切换产生的日志事件）> 最新写入的会话文件（兜底，带迟滞防抖）。 |
| FR2-3 | 显示的会话标识必须能与侧边栏对上（用标题，而不是仅 id 前 8 位）。 |
| FR2-4 | **切换检测（实测修正 v1.0 的描述）**：点击切换会话时 ZCode 即时写 `session.resumed` 事件（子代理同类事件按 `sess_subagent_` 前缀过滤），归属在下一个轮询周期内跟过去——v1.0 所写「纯浏览式切换检测不到」不成立。 |
| FR2-5 | **切换到无数据会话的显示**：目标会话从未生成过内容时没有速率可显示，窗口须显示「该会话暂无生成数据」（数字为 —）并把会话标识切到新会话，**不得**继续显示原会话的数字。例外：切换瞬间其他会话正在生成（最近 5 秒内有 rollout 写入）时，视为日志信号过期，继续显示正在生成的会话。目标会话产生第一次生成后自动开始显示。 |

### FR3 子代理不统计

| 编号 | 需求 |
|---|---|
| FR3-1 | 子代理会话（id 前缀 `sess_subagent_`）的模型请求不计入任何显示数字。 |
| FR3-2 | 子代理活动不得影响会话跟随：不能因为某个子代理在生成而把窗口切到它上面。 |
| FR3-3 | 现状依据（实测，2026-09-28）：rollout 目录只落主会话文件（当时 3 个文件、0 个子代理文件），子代理天然无真值来源；日志事件按 id 前缀过滤。若未来 ZCode 为子代理落盘，本条过滤规则必须继续生效——这是**回归项**，不是可以遗忘的实现细节。 |

### FR4 可靠性（伴随需求）

| 编号 | 需求 |
|---|---|
| FR4-1 | 单实例运行；重复拉起立即退出，不报错。 |
| FR4-2 | ZCode 未运行、无任何数据时显示空闲态，而非报错或空白崩溃。 |
| FR4-3 | 数据源格式变化时必须可诊断：暴露「认出的记录数 / 读到但未认出的行数 / 错误」供排查（status.json）。 |

### FR5 窗口形态：半透明

| 编号 | 需求 |
|---|---|
| FR5-1 | 小窗为半透明：默认不透明度 0.8，可用 `-Opacity` 在 0.3–1.0 调整。 |
| FR5-2 | 半透明不得损害可用性：文字不得出现彩边或发糊（分层窗口上须退回灰度抗锯齿渲染，ClearType 在透明底上会混出彩边）；置顶、拖动、关闭行为不变。 |

### FR6 跟随 ZCode 主窗口

| 编号 | 需求 |
|---|---|
| FR6-1 | ZCode 主窗口关闭后，小窗自动退出（进程结束，不留孤儿置顶窗）。 |
| FR6-2 | ZCode 主窗口最小化（或窗口被隐藏，如最小化到托盘）时，小窗一并收起；恢复时小窗弹回原位。 |
| FR6-3 | 识别必须可靠：主窗口按「标题 `ZCode` + 进程名 `ZCode`」定位；ZCode 是 Electron 窗口（类 `Chrome_WidgetWin_1`），实测 `FindWindow`/`FindWindowEx` 搜不到，必须走 `EnumWindows`。从未找到过 ZCode 窗口时（如手动裸跑脚本）不做任何动作，避免误关。 |

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR1 | 性能：稳态 CPU < 1% 单核；单次刷新 < 50ms。 |
| NFR2 | 资源与安全：对 ZCode 数据**只读**，绝不写入；不联网。 |
| NFR3 | 兼容：Windows + PowerShell 5.1 可运行；200% DPI 缩放下渲染清晰。 |
| NFR4 | 可降级：任一辅助信号缺失（如无 node 运行时）不崩溃，退化为简化显示并明示「精简模式」。 |

## 6. 数据源与约束（需求的可行性边界）

需求建立在这些**无官方 API 保证**的内部文件之上，ZCode 升级后字段可能变（对应 FR4-3）：

| 数据源 | 用途 | 关键实测约束 |
|---|---|---|
| `~/.zcode/cli/rollout/model-io-<sessionId>.jsonl` | TPS 真值（`outputTokens`、`durationMs`） | 一次请求结束后才落盘（单次可 30–60s）；单条记录可达数 MB；只含主会话文件 |
| `~/.zcode/cli/log/zcode-YYYY-MM-DD.jsonl` | 会话激活事件、在飞判定 | 生成期间无逐块事件（26.2s 窗口仅 19 条、首尾成对）；token 数被 Redacted，不可用 |
| `~/.zcode/cli/db/db.sqlite`（`session` / `part` 表） | 会话标题、在飞字节进度 | `part` 落库为中位 3.5s 一次的跳跃式补齐；`time_updated` 无索引，按时间扫全表约 241ms，查询必须由 session_id 走索引 |
| 子代理标识 | FR3 过滤依据 | 日志实测样本：`sess_subagent_agent_6e811dad-…` 等，前缀 `sess_subagent_` 稳定出现（2026-09-28 当日日志 1100+ 条/个） |

由数据源直接派生的两条**需求级限制**（不是实现缺陷，写在这里防止被当 bug 反复报）：

1. 「实时」的更新粒度受落盘粒度限制：真值只能在一流式生成结束时出现；
   生成中的连续反馈靠 FR1-2/FR1-3 的在飞信号，且估算必须标注。
2. `durationMs` 含 TTFT，显示值是端到端速率。

## 7. 验收标准

| 编号 | 覆盖需求 | 标准 | 测量方式 |
|---|---|---|---|
| A1 | FR1-2 | 生成中界面每 ≤1s 有可见变化 | 录屏逐帧核对 |
| A2 | FR1-2 | 空闲与生成中 1 秒内可区分 | 同上 |
| A3 | FR1-1 | 显示值与 rollout 真值重算结果一致 | 抽样核对 ≥10 次 |
| A4 | FR1-3 | 在飞估算与随后到达的真值偏差 ≤20%（20 次配对统计） | 请求完成时对比 |
| A5 | FR2-1/2/3 | 两会话并发生成，各自数据并列正确、标题与侧边栏一致 | 受控并发测试 |
| A6 | FR3 | 子代理活动期间：显示目标不变、数字不进入统计 | 构造子代理活动验证 |
| A7 | FR4/NFR4 | 无 node / 数据缺失时降级运行、不报错 | 故障注入（改名 node、坏快照） |
| A8 | NFR1 | 稳态 CPU < 1% 单核 | 任务管理器 / `Get-Process` 采样 |
| A9 | FR1-6/7 | 最高与平均 TPS 与从 rollout 重算结果一致（最高 = 逐请求取最大；平均 = Σ/Σ） | 抽样核对 |
| A10 | FR5 | 半透明下文字清晰无彩边，置顶/拖动/关闭不受影响 | 目测 + 交互检查 |
| A11 | FR6 | ZCode 最小化 → 小窗收起；恢复 → 小窗弹回；关闭 → 小窗进程退出 | 驱动 ZCode 窗口状态逐一验证（最小化/恢复可实测；关闭由同一检测环覆盖） |
| A12 | FR2-5 | 切到无数据会话 → 等待态（数字 —、提示文案、id 切换）；该会话首次生成 → 自动开始显示 | 合成日志/rollout 的受控测试 |

A4 同时是在飞估算功能（FR1-3）的放行门槛：不过则砍掉估算，只保留真值与在飞状态。

## 8. 范围外（非目标）

- 子代理的独立展示（只要求「不统计」，不要求「展示子代理自己的速率」）。
- 历史报表、导出、跨天聚合统计。
- 内嵌 ZCode 界面 / 复刻其 UI（插件系统无 UI 扩展点，见 §1）。
